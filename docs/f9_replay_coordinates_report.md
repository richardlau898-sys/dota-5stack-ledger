# 方案设想（未实测）

## 一、未实测说明

本方案文档仅记录逐秒真实走位数据的流水线设想，尚未在真实录像文件上运行实测。未能完成真实录像实测的原因如下：

- 仓库内保存的历史样本比赛均已超过官方录像保留期限，原始录像文件已无法从官方服务器下载。
- 当前本地开发与持续集成环境未安装 Java 运行环境或容器运行时，无法启动 `odota/parser` 解析真实录像包。
- 仓库中的 `tools/simulate_replay_coordinates.py` 仅使用合成数据验证字段转换与 `gzip` 压缩代码路径，其输出属于合成数据，不能作为真实耗时或真实文件体积依据。

---

## 二、目标链路设想

待后续具备 Java 运行环境并取得保留期内的新近比赛录像后，计划按以下步骤执行真实端到端验证：

- **获取录像地址**：从已解析比赛的原始返回数据中读取 `replay_url`，或由比赛编号、集群编号与校验盐值拼接录像包下载地址。
- **解压并解析录像**：在赛后离线工作流中下载压缩录像包，解压后送入 `odota/parser` 流式输出事件行。
- **提取逐秒位置**：仅过滤 `type` 为 `interval` 的逐秒记录，按玩家槽位组装 `[time, x, y]` 坐标序列，丢弃其余无关字段。
- **压缩与归档存储**：将紧凑序列化后的轨迹结构经标准库 `gzip` 压缩后上传至 `Supabase Storage` 对象存储桶，供前端时间轴与小地图按需拉取回放。

---

## 三、待实测确认项

在正式接入线上展示之前，需用新近比赛的真实录像补齐以下实测记录：
